GPU Local LLM Hardware

คำนวณ Tokens/sec ก่อนซื้อ GPU — ไม่ให้ซื้อผิด

สูตรง่ายๆ ที่ใช้ทำนายความเร็ว LLM inference จาก spec hardware — bandwidth, wattage, overclock — สำหรับทั้ง NVIDIA GPU และ Apple Silicon Mac

1. สูตรเดียวที่ต้องรู้

Token generation (decode) ถูกจำกัดด้วย memory bandwidth ไม่ใช่ compute — ทุก token ใหม่ต้องอ่าน model weights ทั้งหมด 1 รอบ ดังนั้น:

3 Model ที่ใช้ — หลัก + ทางเลือก

* GSQ-RCO = non-uniform quantization (ISTA-DASLab) คุณภาพดีกว่า Q3_K ปกติที่ขนาดเท่ากัน — decode เร็วเพราะไฟล์เล็ก, prefill เท่าเดิมเพราะ FLOPs ขึ้นกับ params ไม่ใช่ quant

Token Generation Rate
tokens/sec ≈ Memory Bandwidth (GB/s) ÷ Model Size (GB)
ความเร็วจริง = 50–70% ของค่านี้ (overhead จาก kernel launch, sampling, KV cache)

จบ. ถ้าจำได้แค่อย่างเดียวจากบทความนี้ จำสูตรนี้ ที่เหลือคือรายละเอียด

ตัวอย่างเร็ว

RTX 4090 (1008 GB/s) + Qwen3.8-27B Q4_K_M (17.4 GB) — หลัก
→ 1008 ÷ 17.4 = 58 tok/s (theoretical) → ~29-40 tok/s (real)

RTX 4090 (1008 GB/s) + Qwen3.8-27B GSQ-RCO Q3 (10.1 GB) — เร็วขึ้น
→ 1008 ÷ 10.1 = 100 tok/s (theoretical) → ~50-70 tok/s (real)

RTX 4090 (1008 GB/s) + Qwen3.6-35B-A3B Q4 (22.3 GB, MoE active 3B) — ทางเลือก
→ 1008 ÷ 22.3 = 45 tok/s (theoretical) → ~23-32 tok/s (real)

M2 Ultra (800 GB/s) + Qwen3.8-27B Q4_K_M (17.4 GB)
→ 800 ÷ 17.4 = 46 tok/s (theoretical) → ~23-32 tok/s (real)
Rule of thumb: เอา bandwidth ÷ ขนาด model (GB) = tok/s ceiling แล้ว × 0.5–0.7 ได้ค่าจริง ใช้ได้ทั้ง NVIDIA และ Apple Silicon

Prefill (prompt processing) — คนละสูตรกับ decode

ตอนที่ model อ่าน prompt (prefill) ถูกจำกัดด้วย compute ไม่ใช่ bandwidth — ทุก token ใน prompt ต้องคูณ matrix ผ่านทุก layer 1 ครั้ง (กฎ 2N):

Prefill Speed
prefill tok/s ≈ GPU FLOPS ÷ (2 × Parameters)
เวลาอ่าน prompt = prompt_tokens ÷ prefill tok/s — ยิ่ง prompt ยาว ยิ่งรอแรกนาน (TTFT)
Qwen3.8-27B dense (2×27B = 54 GFLOPs/token), prompt 65,000 tokens:

RTX 5090 (~170 TFLOPS) → 21 วินาที
RTX 4090 (~82 TFLOPS)  → 43 วินาที
M2 Ultra (~27 TFLOPS)  → 130 วินาที

Qwen3.6-35B-A3B (MoE 35B แต่ active แค่ 3B → 6 GFLOPs/token):

RTX 5090 → 2 วินาที   (MoE prefill เร็วมาก เพราะ active น้อย)
RTX 4090 → 5 วินาที
M2 Ultra → 14 วินาที
Decode → ดู Bandwidth | Prefill → ดู FLOPS
2 phase คนละ bottleneck — GPU แรงแต่ VRAM ช้า = prefill เร็ว decode ช้า

Context Length = 65,000 tokens — ผลคืออะไร

context ยาว 2 อย่าง: prefill ช้าลง (ต้องคูณ matrix ทุก token) และ decode ช้าลงนิดหน่อย (ต้องอ่าน KV cache เพิ่มจาก VRAM) แต่ Qwen3.8-27B ใช้ hybrid attention (3:1 linear : full) — มีแค่ 16 จาก 64 layer ที่เก็บ KV แบบปกติ ที่เหลือเป็น linear state ขนาดคงที่ KV cache เลยเล็กมาก

KV Cache สำหรับ Qwen3.8-27B ที่ 65K context
2 × 4 (KV heads) × 256 (head_dim) × 2B × 16 (full layers) = 64 KB/token
65,000 tokens → 4.26 GB — เล็กกว่า model (17.4 GB) เยอะ เพราะ linear attention ไม่โตตาม context
Prefill 65,000 tokens (2×27B = 54 GFLOPs/token):

RTX 5090 (~170 TFLOPS) → 21 วินาที
RTX 5080 (~120 TFLOPS) → 29 วินาที
RTX 4090 (~82 TFLOPS)  → 43 วินาที
RTX 3090 (~70 TFLOPS)  → 50 วินาที
M2 Ultra (~27 TFLOPS)  → 130 วินาที (2 นาที)
Decode ที่ 65K context (weights 17.4GB + KV 4.26GB = 21.7GB ต่อ token):

                สั้น ctx    65K ctx    ต่าง
RTX 5090        65 tok/s →  52 tok/s   -20%
RTX 5080        35 tok/s →  28 tok/s   -20%
RTX 4090        36 tok/s →  29 tok/s   -20%
RTX 3090        34 tok/s →  27 tok/s   -20%
M2 Ultra        29 tok/s →  23 tok/s   -20%
ข้อดีของ hybrid attention: context 65K ทำให้ decode ช้าลงแค่ ~20% และกิน VRAM เพิ่มแค่ 4.26GB — ถ้าเป็น transformer ธรรมดา (เก็บ KV ทุก layer) KV cache จะใหญ่กว่านี้ 4 เท่า (~17GB) decode ช้าลง ~50% และ 16GB VRAM ไม่พอเลย

3. Overclock — อันไหนช่วยจริง

GPU Core Overclock — ❌ แทบไม่ช่วย decode

Decode ถูกจำกัดด้วย memory — GPU core นั่งรอ weights มา Core OC จาก 2.5 → 2.8 GHz ได้ประมาณ 2–5% เท่านั้น ไม่คุ้มกับความร้อนและความเสี่ยง

VRAM Memory Overclock — ✅ ช่วยจริง

OC memory clock ตรงๆ เพิ่ม bandwidth ได้ 10% = ได้ ~7–10% tok/s — นี่คือ overclock เดียวที่มีผลกับ inference

ตัวอย่าง RTX 4090:
Stock:       21 Gbps → 1008 GB/s → ~130 tok/s
+10% mem OC: 23.1 Gbps → 1108 GB/s → ~143 tok/s (+10%)

GPU core OC: +200 MHz → ได้แค่ ~3% (noise)

Apple Silicon — ❌ OC ไม่ได้

Bandwidth ถูก fix โดย SoC design ไม่มี knob ให้ปรับ — ซื้อมาเท่าไหร่ได้เท่านั้น จริงๆ แล้วเป็น feature — ไม่ต้อง tune เสถียร

อย่าซื้อ GPU เพราะ overclock headroom — ซื้อจาก stock bandwidth 10% ที่ได้จาก mem OC เป็น bonus ไม่ใช่เหตุผลเลือก GPU

6. ข้อผิดพลาดที่พบบ่อย

เข้าใจผิดทำไมผิดควรทำอย่างไร
"ต้องการ CUDA cores เยอะ"Decode ถูกจำกัดด้วย bandwidth ไม่ใช่ computeดู memory bandwidth แทน
"OC แล้วจะเร็วขึ้น"Core OC ได้ ~3% — มีแค่ mem OC ที่ช่วยซื้อจาก stock bandwidth
"8GB VRAM พอ"27B ต่ำสุด (GSQ-RCO Q3) = 10.1GB — 4GB ใส่ไม่ได้เลย16GB ขั้นต่ำ (Q3), 24GB ใช้ Q4/35B-A3B สบาย
"Mac ช้าสำหรับ AI"M2 Ultra มี 800 GB/s — เร็วกว่า GPU ส่วนใหญ่เทียบ bandwidth ไม่ใช่ "GPU vs Mac"
"cloud API คุ้มกว่า"รายเดือนสะสม — ซื้อ hardware ครั้งเดียวจบคำนวณ: ราคา GPU ÷ ค่า API ต่อเดือน = เดือนคืนทุน

สรุป

tok/s = Bandwidth (GB/s) ÷ Model Size (GB)
ค่าจริง × 0.5–0.7

นั่นคือ 80% ของสิ่งที่ต้องรู้ ที่เหลือ:

→ Memory bandwidth คือ spec เดียวที่สำคัญสำหรับ decode
→ Mem OC ช่วย ~10% Core OC ไม่ช่วย
→ Mac ชนะ perf/watt NVIDIA ชนะ raw speed และ ecosystem
→ VRAM size กำหนดว่ารัน model ไหนได้
→ RTX 3090 มือสอง คุ้มสุดในแง่ bandwidth ต่อราคา
